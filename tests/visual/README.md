# Tailwind migration browser evidence

This is a separate, synthetic-service comparison lane for the Tailwind 3 → 4 migration. It runs the application's actual entry point, auth hooks, router, pages, component primitives, fonts, and CSS. A test-only Vite plugin replaces only the Firebase module with synthetic browser identity and adds the explicitly labeled shared-component fixture route. All API requests are intercepted; unexpected endpoints or non-font external requests fail. No Express server, dotenvx wrapper, database, Firebase credentials, or paid provider is started.

The accepted baseline is the clean pre-migration checkout at `c611b903ddff1833175ac67226b121d78f0f3c18`. Keep its original dependencies installed. Run the harness from the migration checkout; `LAICA_VISUAL_APP_ROOT` chooses the application source. The server changes its working directory to that root before loading the real Vite/PostCSS config, so Tailwind 3 resolves its own config and content rather than the migration config.

Record the approved baseline, then compare the current source:

```sh
PLAYWRIGHT_BROWSERS_PATH=../playwright-browsers ./node_modules/.bin/playwright install chromium webkit
export PLAYWRIGHT_BROWSERS_PATH=../playwright-browsers
LAICA_VISUAL_APP_ROOT=../laica LAICA_VISUAL_LABEL=baseline LAICA_VISUAL_RECORD=1 npm run test:visual
LAICA_VISUAL_APP_ROOT=. LAICA_VISUAL_LABEL=migration npm run test:visual
```

The default artifact root is the private sibling `../visual-parity`. Set `LAICA_VISUAL_ARTIFACTS` to another private location if needed. `LAICA_VISUAL_BASE_URL=http://127.0.0.1:4175` provides an alternate local port. The comparison never records a missing baseline automatically: absent JSON or images fail. Only explicit `LAICA_VISUAL_RECORD=1` records images, and recording checks the baseline SHA, unchanged tracked source, and the `baseline` label. Golden images and generated evidence are intentionally outside the repository.

The matrix uses Chromium and WebKit at **390×844** and **412×915**, mobile/touch enabled, en-US locale, and America/Los_Angeles timezone. JSON evidence records the observed browser version, viewport, application HEAD, tracked-diff SHA-256, harness SHA-256, installed app dependency versions, application root, and server working directory. The baseline and comparison use the same installed Playwright engines. Application journeys cover returning Settings/inventory/profile/diet/menu/Feedback, guest setup and selection controls, Planning time/cuisine/TicketPass/PrepTray, ReadyCheck, a paused timer, captions, and a synthetic microphone failure. The separate primitive fixture uses a neutral flex/gap wrapper and covers heading/label typography, dark input focus, disabled/outline buttons, Select and Switch; the real App profile journey retains the authentic inline-label spacing check. Controlled motion tests exercise actual Dialog/Select animation composition and Toast swipes. This fixture does not invent a router destination for an unrouted page.

For sampled rendered elements, bounds must remain within **1 CSS pixel**, typography, padding and border dimensions must match, text line counts must match, and painted RGBA color channels must match. Canvas color normalization permits equivalent modern `color()`/`color-mix()` syntax without accepting different colors. An outline with zero width or `outline-style:none` paints transparently; its unused computed color is retained in raw evidence and normalized only for painted-color comparison. Painted outlines remain strict and focus rings remain screenshot-covered. Horizontal document/body overflow beyond **1 pixel** fails. Existing inventory helpers also verify scroll/dock/navigation geometry and 44-pixel targets. Screenshots use a **0.5% maximum differing pixel ratio** and **0.1 color threshold** to tolerate minor rasterization noise while exposing broad visual changes; these complement stricter computed-layout checks. The changing timer clock alone is masked. Transient journey toasts are dismissed through their real Close controls before comparison; dedicated motion tests exercise toast behavior. The focused setup input is explicitly scrolled into view, and the pointer moves off controls to avoid persistent mouse hover artifacts in touch screenshots. Paint frames and transitions are drained before sampling, and a baseline-versus-itself replay checks fixture stability. Console exceptions and unknown requests fail; deliberate synthetic microphone/speech failures are separately recorded. Animation tests pause the components' actual CSS animations at chosen frames rather than relying on click timing.

Evidence is fixture-labeled. It does **not** prove live Google/Firebase/App Check, real microphone/camera hardware, paid speech/AI, database persistence, Replit environment, production behavior, or unsampled visual surfaces. This migration lane is change-specific evidence, not the required full regression gate: the exact-head GitHub service-backed guest/linked E2E, unit/eval/static/build checks and audit retain their independent requirements. Replit checks remain deferred to full/release regression under Wilson's workflow instruction.
