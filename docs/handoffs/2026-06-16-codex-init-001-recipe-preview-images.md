## Summary

This branch implements the Phase 3.1 recipe preview imagery pipeline without putting images on the recipe-generation critical path. Chef It Up still reveals the three Ticket Pass suggestions immediately with existing placeholders; image URLs hydrate later only when the resolver has an approved image for all three current options.

The implementation adds a strict cache/fairness discipline: cache matches use normalized title + cuisine + core pantry ingredients, object keys are opaque hashes, generated bytes live in Replit App Storage, runtime generation is gated off until explicitly enabled, and partial image sets never visually favor one recipe over another.

## Changes

- `shared/schema.ts`: adds `recipe_image_cache` metadata for cache key, normalized fingerprint, provider/model/quality/output size/style version, status, App Storage object key, same-origin image URL, MIME type, accuracy result, failure reason, and timestamps.
- `server/recipe-images.ts`: adds the resolver, strict fingerprint/cache-key helpers, OpenAI `gpt-image-2` low-quality generation wrapper, vision accuracy judge, App Storage upload/download adapter, active batch guard, and opaque image-serving route handler.
- `server/routes.ts` and `server/rate-limit.ts`: add authenticated `POST /api/recipe-images/resolve`, public opaque `GET /api/recipe-images/:cacheKey`, and recipe-image-specific rate limits.
- `client/src/lib/openai.ts`: adds the structured resolver API wrapper.
- `client/src/components/cooking/meal-planning.tsx`: strips partial legacy image sets, starts background resolver polling after recipe text generation, aborts stale polls on refresh/back/select/unmount, and applies `imageUrl` only when all three current recipes are ready.
- `scripts/recipe-image-cache-fixtures.json` and `scripts/seed-recipe-image-cache.ts`: add a curated-library seed path that computes the same opaque cache/object keys and only upserts ready rows after approved App Storage objects exist.
- Tests: adds strict cache tests, recipe image route tests, MealPlanning all-or-none hydration tests, and provider-light Playwright coverage for complete-set image reveal.
- Docs: updates INIT-001, the Phase 3.1 phase record, and EFF-010. EFF-022 is cited as related but unchanged because recipe suggestion prompts/cuisine behavior did not change.

## Impact on other agents

- Runtime image generation is intentionally off until `RECIPE_IMAGE_GENERATION_ENABLED=true`; cache hits can still serve while generation is disabled.
- Default provider config is OpenAI `gpt-image-2`, `quality=low`, `1024x1024`, style version `phase-3-1-v1`. `RECIPE_IMAGE_PROVIDER=gemini` is reserved for a later pilot and returns unavailable in v1.
- The image route is public by design because browser image tags cannot send Firebase bearer auth. The cache key/object key is opaque and no user identifiers, emails, raw prompts, or profile data are included.
- Do not run `npm run db:push` locally just to add `recipe_image_cache`. Coordinate schema application through the Replit-authoritative path per EFF-010.
- Pre-generated image fixtures are safe only after the approved object exists at the computed App Storage key. The seed script refuses to seed missing objects.
